# Тестовый стенд: Intel + NVIDIA, Windows + Linux

**Русский** · [English](test_stand.en.md)

Основной компьютер разработки — AMD Radeon RX 9070 (Windows). Чтобы движок проверялся на всех трёх семействах
видеокарт, собран отдельный стенд: встроенная графика Intel (массовая графика офисных машин) и NVIDIA RTX 3060.
Стенд работает с двумя ОС на одном диске и доступен по SSH. Сборку, тесты, снимки кадров и отладочные слои GPU
на нём можно запускать без участия человека.

## Оборудование и программы

| | |
|---|---|
| Процессор | Intel Core i5-10400 (6 ядер / 12 потоков), встроенная Intel UHD Graphics 630 |
| Видеокарта | NVIDIA GeForce RTX 3060 (GA106) |
| Память, диск | 16 ГБ DDR4, SSD 512 ГБ (обе ОС) |
| Windows | Windows 11 Pro; драйверы Intel 31.0.101.2145, NVIDIA 32.0.16.2114 |
| Windows: сборка | MinGW-w64 GCC 15.2 + make; Visual Studio 2022 Build Tools (MSVC 14.44); CMake; Vulkan SDK 1.4.363; Graphics Tools (D3D12 Debug Layer) |
| Linux | Альт p11 (11.2), ядро 6.12, Mesa 26.1.8, проприетарный драйвер NVIDIA 595 |
| Linux: Vulkan | NVIDIA (проприетарный), NVK (Mesa, RTX 3060), ANV (Mesa, Intel), lavapipe (CPU) |
| Linux: сборка | GCC, clang 19, make, CMake, Valgrind 3.24, Vulkan Validation Layers 1.4.335 |

В Windows и в Linux включён автоматический вход: тесты живого окна идут в настоящем графическом сеансе.

## Выбор видеокарты

`GRAN_ADAPTER=<часть имени>` (без учёта регистра) выбирает карту для D3D12, D3D11 и Vulkan:
`GRAN_ADAPTER=intel`, `GRAN_ADAPTER=nvidia`. Если карты с таким именем нет, движок выдаёт ошибку
`GPU_ADAPTER_NOT_FOUND` со списком найденных карт, а не переходит молча на WARP или lavapipe: иначе тест
«прошёл бы» не на той карте. Без переменной D3D12 и Vulkan берут самую производительную карту (на стенде — NVIDIA),
D3D11 — первую в списке DXGI (на стенде — Intel).

На Linux карта NVIDIA работает либо с проприетарным драйвером, либо с NVK. Для NVK в GRUB есть отдельный пункт
загрузки (`gran-nvk`): проприетарный модуль не подключается к карте, nouveau загружается до выбора драйвера X11.
Обычная загрузка — с проприетарным драйвером.

## Что проверяется

| Проверка | Windows | Linux |
|---|---|---|
| Модульные тесты | `make test`; CMake + MSVC: `ctest` | `make test` |
| Отчёты о сбое | `make test-crash` | `make test-crash` |
| Отрисовка на WARP / lavapipe, сравнение с эталонами | `make test-render` | `bin/gran_linux_tests` |
| Отрисовка на видеокарте | `GRAN_ADAPTER=<карта> bin/gran_render_tests --d3d12 --hardware` (и `--d3d11`) | `GRAN_ADAPTER=<карта> bin/gran_linux_tests --hardware` |
| Живое окно | те же тесты в сеансе пользователя (перезагрузка разметки, смена размера); `gran_gallery --exit-after N` | `bin/gran_linux_tests --window [--hardware]` |
| Снимки всех `samples/*.xml` с отладочными слоями | `GRAN_GPU_VALIDATION=1 bin/gran_snapshot … --d3d12` и `--d3d11`; любое сообщение слоя — ошибка | `make DEBUG=1`, `bin/gran_snapshot … --vulkan` с `VK_LAYER_KHRONOS_validation` |
| Санитайзеры | CMake + MSVC `-DGRAN_SANITIZE=address`, `ctest` | `make DEBUG=1 SANITIZE=address,undefined test`, `SANITIZE=thread`, Valgrind memcheck |

Тесты живого окна в Windows нельзя запускать прямо из сеанса SSH: у него нет рабочего стола, и создание цепочки
обмена возвращает `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE` (0x887A0022). Их запускают разовой задачей планировщика
в сеансе вошедшего пользователя. Установщики Windows (компоненты, драйверы, Build Tools) из сеанса SSH получают
«Access is denied»; их запускают задачей от имени SYSTEM.

## Результаты

### 2026-11-08 — первый прогон

**Windows 11**

| Проверка | Итог |
|---|---|
| MinGW: модульные тесты | 343/343 (по SSH и в сеансе пользователя) |
| MinGW: отчёты о сбое | прошло |
| WARP D3D12 и D3D11: 4 кадра + перезагрузка разметки + backend | прошло, пиксель в пиксель |
| RTX 3060 D3D12 и D3D11 | прошло, отличие от эталонов WARP ≤ 2 единиц |
| Intel UHD 630 D3D12 и D3D11 | прошло, отличие ≤ 2 единиц; карта подтверждена журналом программы |
| Снимки 21 разметки × D3D12 (с GPU-Based Validation) и D3D11, на Intel и на NVIDIA | 84 кадра, ни одного сообщения отладочного слоя |
| `gran_gallery`, 5 минут в живом окне (NVIDIA) | прошло |
| MSVC 14.44, выпуск: `ctest` | 4/4 после исправления «Берёсты» (до него — 144 из 342 модульных тестов падали) |
| MSVC 14.44 ASan: `ctest` | модульные тесты и отрисовка чистые; проба сбоя с ASan не совместима и при санитайзере не собирается |

**Найдено и исправлено**

1. **MSVC 14.44 /O2 неверно компилировал выбор `a|b|c` в регулярных выражениях XSD «Берёсты»**: средние варианты
   выбора из трёх и более ветвей были недостижимы. В Грани UI это ломало проверку цвета вида `#172033`.
   GCC, MSVC 14.51 и отладочные сборки не затронуты, поэтому на основном компьютере ошибка не проявлялась.
   Исправлено в «Берёсте» (цикл `compileAlternation` переписан), регрессионный тест добавлен в её набор.
2. **CMake + MSVC с `GRAN_SANITIZE=address` не компоновался** (LNK2038 `annotate_string`): «Берёста» собиралась
   без ASan. Санитайзер теперь применяется и к `beresta_objects` / `beresta_static`.
3. **Проба сбоя `gran_crash_reports` зависала под ASan**: ASan перехватывает намеренный сбой раньше обработчика
   движка. При санитайзере тест не собирается.
4. **Не было способа выбрать видеокарту**: D3D12 всегда брал NVIDIA, D3D11 — Intel. Добавлен `GRAN_ADAPTER`.
5. **GPU-тесты Linux проверяли только lavapipe**: добавлен ключ `--hardware`.

Изменения Linux-кода этого прогона (`--hardware`, отказ от подмены карты на lavapipe при `GRAN_ADAPTER`) сначала
проверены в WSL Ubuntu, затем на стенде (ниже).

6. **Фабрика бэкенда Linux подменяла выбранную карту на lavapipe** при любой ошибке GPU — при `GRAN_ADAPTER`
   подмена отключена (найдено при проверке `--hardware` в WSL).
7. Предупреждение GCC `-Wformat-truncation` в `json_reader_scan.cpp` (байт ошибки JSON) убрано.

**Linux (Альт p11)**

Рабочий стол — GNOME в сеансе Wayland; тесты окна X11 идут через XWayland. GPU-тесты — отладочная сборка
(`make DEBUG=1`), в ней подключается `VK_LAYER_KHRONOS_validation` (проверено журналом загрузчика Vulkan).

| Проверка | Итог |
|---|---|
| Сборка выпуска и отладки (GCC) | без предупреждений; выпуск — 2 мин 9 с на 12 потоках |
| Модульные тесты, отчёты о сбое | 338/338, прошло |
| `gran_linux_tests --hardware` + снимки 21 разметки: NVIDIA (проприетарный 595), Intel ANV, lavapipe | прошло; ни одного сообщения проверочного слоя; кадры разных драйверов различаются — карта выбрана действительно та |
| То же на NVK (пункт GRUB `gran-nvk`) | тесты бэкенда прошли; снимки — см. находку 8 |
| Окно X11 (`--window`): NVIDIA, NVK, lavapipe | прошло |
| Окно X11 на Intel | `vkCreateSwapchainKHR` → `VK_ERROR_INITIALIZATION_FAILED` — ограничение платформы, см. находку 9 |
| ASan + UBSan (`make DEBUG=1 SANITIZE=address,undefined test`) | 338/338, без замечаний |
| TSan (`SANITIZE=thread`) | 338/338, без предупреждений |
| Valgrind memcheck (`gran_tests`) | 338/338, 0 ошибок |

**Найдено на Linux (не ошибки движка)**

8. **NVK (Mesa 26.1.8, ядро 6.12.94, RTX 3060): каждый второй процесс зависает на первой отправке команд.** После
   выхода любого процесса, работавшего с картой, первая отправка следующего не завершается: ядро пишет
   `job timeout, channel N killed`, программа через ~15 с получает `VK_ERROR_DEVICE_LOST`; следующий процесс снова
   работает. Не зависит от разметки, отладочного слоя и вида сборки; так же падает эталонный `vkcube`, и без
   драйвера Vulkan NVIDIA в загрузчике (`VK_DRIVER_FILES`) — то же. Это ошибка nouveau/NVK. Обход на стенде — повтор
   упавшего запуска; при повторе отрисовались все 21 разметки без сообщений слоя.
9. **Intel не выводит в окно, когда рабочий стол работает на NVIDIA.** Композитор GNOME (на проприетарном драйвере
   NVIDIA) не принимает буферы Intel: `vkcube` на Intel падает так же и через Wayland, и через XWayland. Без окна
   (снимки, тесты бэкенда) Intel работает. Чтобы проверить окно на Intel, монитор подключают к выходу материнской
   платы, и рабочий стол запускается на Intel.
10. **Проприетарный драйвер NVIDIA виден в Vulkan дважды** (два файла ICD в Альте). Безвредно: `GRAN_ADAPTER=nvidia`
    берёт первое устройство.
11. **Загрузка Альта после Windows стояла 2 ч 25 мин.** GRUB и ядро отработали сразу (ядро стартовало через 1,5 мин
    после команды перезагрузки). Остановилась служба `plymouth-read-write` (заставка загрузки), а с ней и вся система
    до `sysinit.target` и SSH. Продолжилась, когда к стенду подключили клавиатуру. Экран всё это время показывал
    последний кадр GRUB, поэтому зависание выглядело как ожидание в меню. Лечение для стенда — загрузка без заставки
    (Т-13).
12. **Часы.** Windows хранит в аппаратных часах местное время, а часовой пояс там — тихоокеанский (UTC−8). Альт
    поэтому стартует с часами на 8 ч позади, пока их не поправит NTP. Для `make` это опасно: файлы «из будущего»
    ломают пересборку. Лечение — Т-13.
13. **Стенд засыпает через 15 минут** без ввода с клавиатуры и мыши: GNOME в сеансе автовхода не считает работу по SSH
    активностью. Долгие прогоны запускаются под `systemd-inhibit --what=sleep:idle`; совсем отключить сон — Т-13.

**Ручная проверка Т-14 (Windows, Intel и NVIDIA): найдено и исправлено**

14. **После быстрого перетаскивания края окно зависало на секунды, по краям — чёрные и белые полосы.** Каждое событие
    смены размера, накопленное за время модального цикла Windows, пересоздавало цепочку обмена под устаревший размер.
    Замер на 300 шагах: Intel D3D12 — 2,8 с, Intel D3D11 — 1,0 с, NVIDIA — 0,4–0,7 с (AMD — до 0,9 с); после
    исправления — около 1 мс. Тест «live resize storm» в `gran_render_tests`; повторная проверка глазами — Т-15.

**Ручная проверка Т-15 (Windows, Intel и NVIDIA): найдено и исправлено**

15. **Пока край быстро тянут туда-обратно, у растущего края — белые и чёрные полосы.** Зависания после Т-14 нет, но
    DWM показывает окно нового размера раньше, чем приходит кадр GPU этого размера, и в выросшей полосе видна
    поверхность перенаправления окна. Окно её не закрашивало (`WM_PAINT` только вызывал `ValidateRect`), отсюда
    белое и чёрное. Теперь она закрашивается сплошным фоном окна, и полоса сливается с фоном.
    Замер — `gran_render_tests --d3d12|--d3d11 --hardware --resize-artifacts` в сеансе с рабочим столом. Он берёт
    угол витрины настоящей мышью (`SendInput`): 40 шагов по 20 пикселей через 4 мс, три раза вправо-влево. Подложка
    серая, а кадры монитора снимаются через Desktop Duplication, поэтому белое и чёрное в полосе — только мусор окна.
    Плохих кадров было: Intel D3D12 — 120 из 376, Intel D3D11 — 88 из 386, NVIDIA D3D12 — 34 из 391, NVIDIA D3D11 —
    28 из 405. После исправления — 0 везде.
    Два ложных пути замера, чтобы не повторять:
    - снимок экрана через GDI (`BitBlt`) заставляет DWM собрать свежую композицию и промежуточных кадров не видит;
    - `SetWindowPos` из кода вместо мыши и рост окна в одну сторону мусора почти не дают.
    Тест двигает курсор, поэтому в обычный прогон не входит — только на стенде.

**Наблюдение (основной компьютер, AMD RX 9070):** `gran_render_tests --d3d12 --hardware` — в кадре `glass` один
пиксель отличается от эталона WARP на 3 при допуске 2 (размытие); так было и до этого прогона. Эталоны — WARP,
попиксельное равенство между драйверами не заявляется; при сравнении на AMD нужен `--tolerance 3`.
