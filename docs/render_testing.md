# Проверки отрисовки

На Linux `make test-render` запускает CPU Vulkan/Mesa (`tests/linux/`), `make test-window` —
настоящее окно X11/Vulkan. В CMake: `GRAN_BUILD_RENDER_TESTS=ON`, для окон дополнительно
`GRAN_BUILD_WINDOW_TESTS=ON`. Проверяются readback RGBA, ориентация, resize/Kawase, границы буферов,
переиспользование текстуры с двумя кадрами в полёте, diagnostics, XIM/shortcuts, UTF-8 clipboard между
двумя процессами и wake из фонового потока. Khronos validation (включая synchronization validation
при доступном SDK/слое) считается источником ошибок. Для CPU требуется Mesa с lavapipe.
Эталоны WARP остаются Windows-проверкой; междрайверное попиксельное равенство не заявляется.

**Русский** · [English](render_testing.en.md)

GPU-проверки запускаются отдельно от `make test`: модульные тесты работают без устройства GPU.
`tests/render/scenes/` содержит сцены, `tests/render/baselines/` — проверенные эталоны PNG.
Эталоны создаются D3D12 WARP, размер и масштаб фиксированы. Обычный прогон их не меняет.

`make test` также проверяет рамки окна без GPU: XML/роли, ввод и доступность команд, состояние Maximized,
отсечение/преобразования/модальность, а на Windows — настоящие HWND в режимах system/custom, восемь зон
resize, ограничения размера, WM_CLOSE и смену DPI 96→144 через сообщение. Живой пример:
`bin/gran_gallery samples/custom_window.xml --debug`. Snap Layouts зависит от Windows 11 и настроек ОС;
автоматические проверки подтверждают HTMAXBUTTON, появление меню проверяется в живом окне.

## Make

```sh
make test
make test-render
```

Вторая команда собирает `bin/gran_render_tests.exe` и запускает D3D12 и D3D11 на WARP.
Текущие кадры лежат в `scratchpad/render-tests/` (не включаются в Git).

Отдельный API или аппаратный адаптер:

```sh
bin/gran_render_tests --d3d11
bin/gran_render_tests --d3d12 --hardware --tolerance 3 --output scratchpad/render-hardware
```

Сравнивается каждый канал RGBA8; по умолчанию допуск 2. Любой пиксель за допуском, несовпадение размеров,
отсутствующий эталон, ошибка GPU или ошибка отладочного слоя дают ненулевой код возврата.
D3D12 проверяет уровни ERROR/CORRUPTION; D3D11 дополнительно считает провалом предупреждения.
Отладочный слой включается при наличии Windows Graphics Tools; его отсутствие допускается.
Неудачный кадр сохраняется; вывод показывает число несовпавших пикселей и максимальную разницу канала.
`max` может быть ненулевым при успехе, если разница входит в допуск.

На AMD RX 9070 для обеих реализаций максимальная разница с WARP в размытии составила 3 в одном пикселе;
для аппаратных проверок этой машины используйте `--tolerance 3`. Порог проверок WARP остаётся 2.
Между машинами требуются одинаковые шрифты: текстовая сцена использует системный Consolas Windows.
Для другого шрифта нужен отдельный набор эталонов.

## CMake

```sh
cmake -S . -B build -DGRAN_BUILD_RENDER_TESTS=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

На Windows добавляются `gran_render_d3d12` и `gran_render_d3d11`. Кадры находятся в папке сборки,
эталоны читаются из исходников. Для многоконфигурационной сборки добавьте `--config Release` и `ctest -C Release`.
Набор предназначен для Windows 10/11; Linux/macOS пока не имеют готового графического бэкенда.

## Изменение эталонов

После намеренного изменения отрисовки:

```sh
make update-render-baselines
```

Или `bin/gran_render_tests --update`. Обновление разрешено только с D3D12 WARP, чтобы случайный выбор GPU
не изменил происхождение эталона. Просмотрите новые PNG и разницу в Git, затем выполните `make test-render`.
Не обновляйте эталон только для устранения необъяснённого провала.

## Что покрыто

- Скругления, разные рамки, линейный/радиальный/конический градиенты, внешняя тень, поворот, прозрачность,
  отсечение внутри Scroll; масштаб 1 и 1,5.
- Русский/английский текст, оформленные участки, подчёркивание, PNG, прозрачная картинка и Input.
- Две перекрывающиеся подложки с разными радиусами размытия.
- Картинки A/B/A, resize цели, повторное использование слотов и чтение пикселей с учётом шага строки.
- Живое окно: загрузка из таймера откладывается до границы цикла; watcher сохраняет интерфейс при ошибке XML
  и принимает исправление.
- Модульные проверки сравнения: допуск, альфа, несовпадение размеров и длины массива.

Тесты не заменяют проверки на NVIDIA/Intel и разных драйверах. WebView в offscreen не включается.
Анимации в снимках показывают исходное состояние.

## Снимок произвольной разметки

```sh
bin/gran_snapshot samples/glass.xml scratchpad/glass-dx11.png --d3d11 --warp
bin/gran_snapshot samples/showcase.xml scratchpad/showcase.png 1000 760 1.5 --d3d12
```

Ключи можно смешивать с позиционными размерами после двух путей.
Ошибка отладочного слоя завершает инструмент ненулевым кодом.
Компиляторы нужны только при изменении HLSL: `make shaders` (DXIL/dxc), `make shaders-dx11` (DXBC/fxc);
CMake — `gran_shaders` и `gran_shaders_dx11`.
