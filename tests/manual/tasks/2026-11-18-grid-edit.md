# Ручные проверки: правка ячеек DataGrid (2.2.4)

Доработка 2026-11-18: у таблицы с `editable="true"` редактор текущей ячейки открывают F2, Enter, двойной щелчок или
набор символа; Enter записывает, Esc отменяет, Tab/Shift+Tab записывают и открывают соседний столбец, щелчок мимо тоже
записывает. Тип столбца (`text`, `number`, `date`, `boolean`) проверяет значение, ошибка — состояние `<Invalid>`
(красное подчёркивание), редактор не закрывается. Свой редактор — `<EditTemplate>`. Каждая правка — шаг отмены,
запись отслеживается, пока редактор открыт (сортировка, вставка, удаление). Автотесты (`grid edit: *`, `cell value: *`,
`record tracker: *`) проверяют пути клавиш и мыши, запись в модель, отмену и прокси в безоконном приложении; живую
мышь, каретку, вид редактора в ячейке, смену фокуса между окнами и метод ввода они не видят.

Подготовка для всех задач (Windows, MinGW):

```bash
make -j16 all
```

```bash
bin/gran_gallery samples/grid.xml --debug
```

В примере «№» не правится, «Сумма» — число, «Состояние» выбирается списком (`<EditTemplate>` с `ComboBox`).
Отмена — Ctrl+Z / Ctrl+Y, если галерея их привязывает; иначе шаги отмены проверяются автотестами, а здесь пропускаются.

## Т-67. Правка ячеек под живой мышью и клавиатурой (Windows)

- **Зачем.** Редактор встаёт в ячейку между кадрами, забирает фокус и каретку, а уход фокуса записывает значение только
  в безопасной точке после события. Риски, которых не видит тест: строка «прыгает» по высоте, текст редактора стоит не там,
  где стоял текст ячейки, каретка не мигает или стоит не там, выделение значения не видно, двойной щелчок выделяет слово
  вместо открытия редактора, щелчок по другой строке не записывает, редактор остаётся висеть после прокрутки колесом.
- **Приоритет:** до выпуска 0.3.0 · ~25 минут.
- **Подготовка.** Команды выше.
- **Шаги.**
  1. Щёлкните по ячейке «Клиент» третьей строки, нажмите F2.
  2. Наберите «Тест», нажмите Enter.
  3. Нажмите стрелку вниз, затем сразу наберите «Проба» (без F2), нажмите Esc.
  4. Дважды щёлкните по ячейке «Город» любой строки; наберите несколько букв; щёлкните по ячейке другой строки.
  5. Щёлкните по ячейке «Сумма», наберите «12x», Enter. Затем Backspace, Enter.
  6. Наберите в «Сумме» «-3,5», Tab.
  7. В редакторе «Состояние» (открылся после Tab) раскройте список щелчком, выберите другое значение мышью; нажмите
     Enter. Затем откройте этот редактор снова (F2), раскройте список стрелкой вниз, выберите значение стрелками и Enter,
     затем ещё раз Enter.
  8. Щёлкните по «№» и нажмите F2; наберите любую цифру.
  9. Откройте редактор «Клиент» в середине таблицы, наберите текст и покрутите колесо так, чтобы строка ушла за край
     и вернулась.
  10. Отсортируйте по «Клиент» щелчком по заголовку; откройте редактор у первой строки, наберите «Яяя», Enter.
  11. Наберите в поле поиска сверху «Тест» (если запись из шага 2 осталась) — таблица отфильтрована; очистите поле.
- **На что смотреть.**
  1: в ячейке поле ввода, текст стоит на том же месте, что и до F2 (без сдвига вправо или вниз), высота строки не
  меняется, значение выделено целиком (подсветка), каретка в конце; рамка текущей ячейки на месте.
  2: в ячейке «Тест», строка выделена, стрелки снова ходят по таблице (фокус вернулся).
  3: редактор открылся с текстом «Проба» вместо прежнего значения, каретка после «а»; Esc — прежнее значение.
  4: двойной щелчок открывает редактор (не выделяет слово в тексте ячейки); щелчок по другой строке записывает набранное,
  редактор исчезает, выделение переходит на новую строку.
  5: «12x» + Enter — редактор остаётся открытым, значение подчёркнуто красным, текст красный; после исправления Enter
  записывает «12», подчёркивание пропадает.
  6: записано «-3.5» (запятая стала точкой), открылся список «Состояние» той же строки.
  7: раскрытие списка не закрывает редактор; выбор пункта ставит его в поле, первый Enter (или выбор мышью) не
  записывает, пока список открыт, а закрывает список; следующий Enter записывает, плашка меняет цвет (оплачен —
  зелёная, остальные — красная).
  8: редактор не открывается, цифра не появляется нигде.
  9: после возврата строки редактора нет, набранный текст записан в ячейку (а не потерян); фокус у таблицы.
  10: значение записано, строка уехала по сортировке в конец, выделение и текущая ячейка у той же записи.
  11: «Показано N из M» и сумма выделенного внизу пересчитываются после правок суммы.
- **Что прислать.** Отметку «прошло / не прошло» по шагам; скриншот шагов 1 и 5 (крупно ячейку); если что-то «прыгает» —
  короткое видео в `tests/manual/results/`.
- **Результат.** Все норм, дефектов не выявил

  **Разбор (Claude, 2026-11-19).** Прошло: редактор на месте текста ячейки, ошибка числа, Tab, список в редакторе,
  потерянная при прокрутке строка — всё как ожидалось. Человек ничего не нашёл сверх автотестов: пути клавиш и мыши
  уже покрыты `grid edit: *`; что видит только глаз (место текста, каретка, подчёркивание) — подтверждено.

## Т-68. То же на Linux (Альт на стенде)

- **Зачем.** Символы на X11 приходят своим путём (XIM/XLookupString), F2 и Enter цифрового блока — своими кодами;
  двойной щелчок X11 считается движком по времени и расстоянию.
- **Приоритет:** когда будет время · ~15 минут.
- **Подготовка.** На стенде уже лежит и собрано дерево `~/gran-stand/t224` (рабочая копия 2.2.4, `make -j8 all` без
  предупреждений, `make test` 513/513 — 2026-11-19). Если стенд в Windows — перезагрузить в Альт. В терминале сеанса:
  `cd ~/gran-stand/t224 && bin/gran_gallery samples/grid.xml`.
- **Шаги.** Шаги 1–6 и 9 из Т-67; дополнительно — Enter цифрового блока для записи и русская раскладка при наборе
  (наберите «ёжик» в «Клиент»).
- **На что смотреть.** То же, что в Т-67; «ёжик» набирается целиком, первый символ не теряется (он открывает редактор).
- **Что прислать.** Отметку по шагам; при ошибке — строки журнала `gran_gallery` из терминала.
- **Результат.** Все норм, дефектов не выявил

## Т-69. Ревью: сеанс правки, безопасные точки, отслеживание записи

Сначала пройдите [общие пункты ревью кода О-1…О-8](../README.md#code-review-rules), затем переходите к шагам этой задачи.

- **Зачем.** Сеанс правки держит невладеющие указатели на узлы и наблюдателя модели; значение пишется в безопасной точке
  (после события, после подгонки виртуального списка). Ошибки здесь — висячий указатель после удаления строки,
  запись не в ту запись после сортировки, перестройка дерева посреди работы маршрутизатора ввода.
- **Приоритет:** когда будет время · ~40 минут.
- **Что читать.** Все файлы скопированы в одну папку `tests/manual/review/T-69/` (снимок 2026-11-19, номера строк
  совпадают с оригиналами; там же `README.md` — таблица «копия → оригинал»). Оригиналы, в порядке чтения:
  - `include/gran/app/internal/grid_edit.hpp` — устройство сеанса и правила;
  - `src/app/grid_edit_begin.cpp` — открытие редактора;
  - `src/app/grid_edit_editor.cpp` — редактор по типу или `<EditTemplate>`, сеанс;
  - `src/app/grid_edit_value.cpp` — значение редактора;
  - `src/app/grid_edit_finish.cpp` — окончание правки, проверка, запись, безопасная точка;
  - `src/app/grid_edit_watch.cpp` — удаление узлов и смена фокуса во время правки;
  - `src/app/grid_edit_keys.cpp` — Enter, Esc, Tab, двойной щелчок;
  - `src/app/grid_edit_step.cpp` — шаг отмены;
  - `src/app/app_grid_input.cpp` — вход из маршрутизатора ввода;
  - `src/ui/data_grid_edit.cpp` — правимые столбцы и перевод текущего столбца (`moveGridCurrent`) для Tab;
  - `include/gran/data/record_tracker.hpp`, `src/data/record_tracker.cpp`, `src/data/record_tracker_events.cpp` —
    номер записи при `moved`/`reordered`;
  - `include/gran/data/cell_value.hpp`, `src/data/cell_value.cpp`, `src/data/cell_number.cpp`, `src/data/cell_date.cpp` —
    разбор чисел и дат (внешний ввод пользователя);
  - `src/input/character_input.cpp`, `src/input/press_input.cpp` — символ и двойной щелчок у таблицы;
  - вызовы: `src/app/application_events.cpp` (`settleGridEdit` после ввода), `src/app/application_layout.cpp`
    (после подгонки), `src/app/node_removal.cpp` (`gridEditRemoving`), `src/app/window_closing.cpp` (`~State` сбрасывает
    правку до моделей).
- **Что искать.** Указатель сеанса, который может пережить свой узел; путь, где модель меняется изнутри
  `changeFocus`/`dispatch`; утечка подписки `RecordTracker` (окно закрыто, документ перезагружен); переполнения
  в разборе (очень длинные числа и даты, `size_t`); неверный номер записи после `moved` с `to` в новом порядке;
  шаг отмены с неверным номером в хранилище, когда таблица смотрит на фильтрованный прокси.
- **Что прислать.** Ссылки `файл:строка` с замечаниями.
- **Результат.** в grid_edit_begin.cpp на строках 81–84 при повторном начале правки, например при двойном щелчке когда редактор уже открыт или при быстрой передаче ввода. Там beginGridEdit вызывает finishGridEdit(win, true) прямо внутри себя, а сам beginGridEdit вызывается напрямую из обработчиков маршрутизатора ввода AppWindow::listText и AppWindow::listDoubleClick (app_grid_input.cpp:7, 12 и press_input.cpp:89), то есть прямо из середины win.router->handle(event) до безопасной точки settleGridEdit. Внутри finishGridEdit сначала удаляется узел старого редактора через removeNode — это дергает nodeRemoving и treeVersion++ — а потом сразу вызывается source.set(...), меняющий модель и запускающий перестройку дерева строк прямо посередине прохода маршрутизатора ввода, когда у того на стеке лежат живые указатели на узлы вроде pressed или focus. Еще стоит следить за порядком полей в Application::State при закрытии главного окна: в closeWindows (window_closing.cpp:59) state.quit = true ставится без вызова finishWindow, и хотя ~State (window_closing.cpp:80–89) явно сбрасывает win.gridEdit.reset(), тела деструктора потом всё равно разрушают поля State, поэтому windows должны быть объявлены раньше lists, чтобы RecordTracker точно отписался до смерти моделей. По мелочи для улучшения кода: в grid_edit_watch.cpp:54 const_cast на win.router->focused() лишний, так как insideNode и ui::popupOf судя по сигнатурам спокойно работают с const ui::Node*, а в cell_value.cpp:69–72 функция booleanOf(value) вызывается дважды подряд, лучше сохранить её результат в переменную, чтобы не гонять цикл второй раз. В остальном и RecordTracker::moved с to в новом порядке, и разворот прокси в pushCellStep, и парсеры чисел и дат в cell_number.cpp и cell_date.cpp написаны чисто, без переполнений и утечек

  **Разбор (Claude, 2026-11-19).** Четыре замечания, три исправлены, одно — нет ошибки, но по нему найдена другая.
  1. **Правка заканчивалась изнутри маршрутизатора ввода — подтвердилось.** `beginGridEdit` закрывал открытую правку
     (`finishGridEdit` → `removeNode` + `source.set`) прямо из `listText`/`listDoubleClick`/F2, то же делали Enter, Esc и Tab
     в `gridEditorKey`. На практике указатели на стеке после этих вызовов уже не читались, поэтому ни тесты, ни ASan падения
     не видели, — но это держалось на везении, а не на устройстве. Исправлено: правка заканчивается **только в безопасной
     точке** — до и после `router->handle` (`src/app/application_events.cpp`) и после подгонки кадра. Клавиши редактора
     лишь ставят `pending` (новый `SUBMIT`: ошибка проверки оставляет редактор открытым; Tab — `GridTab`), `beginGridEdit`
     при открытой правке возвращает false, переход по Tab — в новом `src/app/grid_edit_settle.cpp`. Тест
     `grid edit: focus from code, then F2` (фокус из кода между событиями, отложенная правка закрывается до F2).
  2. **Порядок полей `Application::State` — ошибки нет**, менять не надо. Поля уничтожаются в обратном порядке
     объявления: `windows` объявлены раньше `lists`, значит, разрушаются **после** них — и именно поэтому `~State` в теле
     (оно выполняется до разрушения полей) сбрасывает `win.gridEdit`. Переставить поля нельзя: привязки `ListBindings`
     ссылаются на узлы окон и должны уйти раньше узлов. Добавлен тест `grid edit: application destroyed with an open edit`,
     ASan подтверждает. **Но замечание навело на настоящую ошибку:** закрытие окна крестиком или Alt+F4 не записывало
     открытую правку — фокус не уходит, и `onClose` сохранял данные без набранного значения. Исправлено: событие `CLOSE`
     сначала записывает правку (`commitGridEdit`); тест `grid edit: closing the window writes the edit` (откат — падает).
  3. **`const_cast` в `grid_edit_watch.cpp` — исправлено**, но не так, как предложено: `insideNode` действительно принимает
     `const`, а `ui::popupOf` — нет (`Node* popupOf(Node*)`), поэтому слой ищется своим `layerOf` через `ui::isLayer`.
  4. **Двойной вызов `booleanOf` в `cell_value.cpp` — исправлено**: слово ищется один раз и только для `BOOLEAN`.
  Что нашёл человек и не поймали автотесты и анализаторы: закрытие правки изнутри маршрутизатора (класс «перестройка
  дерева посреди обработки события» — ASan видит его только при неудачном раскладе) и, по следу, потерю правки при закрытии
  окна. В автоматические проверки: тесты выше; общее правило «конец правки — только в безопасной точке» записано
  в `include/gran/app/internal/grid_edit.hpp`. Проверки: Windows `make test` 523/523, `make all` без предупреждений;
  WSL ASan+UBSan 516/516 чисто. Папка копий `tests/manual/review/T-69/` удалена.
