# Ручные проверки: первый прогон на тестовом стенде (2026-11-08)

Стенд: i5-10400 (Intel UHD 630) + RTX 3060, Windows 11 + Альт p11. Что уже проверено автоматически —
[`docs/test_stand.md`](../../../docs/test_stand.md). Здесь — то, что требует человека у стенда.

## Т-13. Альт не отвечает по SSH после перезагрузки из Windows

- **Зачем.** Дважды после перезагрузки Windows → Альт стенд отвечал на ping, порт 22 принимал соединение, но SSH не
  получал приветствия («banner exchange») больше часа: загрузка где-то стоит. После перезагрузки Альт → Альт всё
  работает. Без этого проверки Linux по SSH после Windows невозможны. Автоматика тут бессильна: нужен экран стенда.
- **Приоритет:** блокирует проверки Linux на стенде; 10–15 минут.
- **Подготовка.** Монитор на выход стенда.
- **Шаги.**
  1. Посмотрите на экран стенда, ничего не нажимая. Сфотографируйте его.
  2. Если на экране сообщение или запрос (проверка диска, «A start job is running…», пароль, экран входа) —
     сфотографируйте и только потом нажмите Enter / войдите.
  3. Когда SSH заработает, напишите мне — я сам посмотрю `journalctl -b` и что задержало загрузку.
- **На что смотреть.** Загрузка дошла до рабочего стола с автовходом или нет; есть ли текстовые сообщения.
- **Что прислать.** Фото экрана (шаги 1–2) — в `tests/manual/results/`.
- **Результат.** Пользователь: на экране был GRUB, выбрал Альт — загрузка пошла, SSH заработал.
- **Разбор.** По журналу GRUB не ждал: ядро стартовало через 1,5 мин после перезагрузки. 2 ч 25 мин стояла служба
  `plymouth-read-write` (заставка), а с ней `sysinit.target` и SSH. Двинулась через 4 с после подключения клавиатуры
  (переключатель USB). На экране оставался последний кадр GRUB, поэтому всё выглядело как ожидание в меню.
  Попутно нашлись часы на 8 ч позади (Windows: пояс UTC−8, аппаратные часы в местном времени) и сон GNOME через
  15 мин без ввода (стенд уснул посреди прогона NVK).
  **Что нашёл человек:** экран показал, где «стоит», а по журналу стало видно, что стоит не GRUB. Автоматика этого не
  ловила. Добавить в проверки: перед прогоном на стенде — `systemd-analyze` (время до `sysinit.target`) и проверка
  разницы часов.
- **Осталось сделать у стенда (системные настройки — за пользователем):**
  1. Альт: в `/etc/default/grub` из `GRUB_CMDLINE_LINUX_DEFAULT` убрать `splash`, затем `update-grub`.
  2. Альт, в сеансе ermaley: `gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'nothing'`.
  3. Windows: часовой пояс «Москва»; в cmd от администратора
     `reg add HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation /v RealTimeIsUniversal /t REG_DWORD /d 1 /f`.
  После этого — одна перезагрузка Windows → Альт без человека у стенда, я проверю время загрузки.

## Т-14. Глазами: галерея на Intel и на NVIDIA (Windows)

- **Зачем.** Снимки на обеих картах совпали с эталонами WARP (≤ 2 единиц), но живой кадр на мониторе 21:9 — шрифты,
  размытие стекла, тени, плавность анимаций на ≤ 60 Гц — автоматика не оценивает.
- **Приоритет:** желательно до выпуска; 15 минут.
- **Подготовка.** Загрузить Windows на стенде. В `cmd`:
  ```
  cd /d C:\gran\gran
  set GRAN_ADAPTER=intel
  bin\gran_gallery.exe
  ```
  Затем то же с `set GRAN_ADAPTER=nvidia`.
- **Шаги.**
  1. Разверните окно на весь экран 3440×1440, прокрутите витрину до конца и обратно.
  2. Откройте `samples/glass.xml` (`bin\gran_gallery.exe samples\glass.xml`), подвигайте окно.
  3. Наведите курсор на кнопки и переключатели — анимации переходов.
- **На что смотреть.** Одинаковая картинка на обеих картах; нет мерцания, полос в градиентах, «лесенки» в тексте,
  рывков анимации; размытие стекла без артефактов по краям.
- **Что прислать.** Скриншоты с обеих карт, если видна разница или артефакт.
- **Результат.** Пользователь: не прошло. Видео в `tests/videos/`. Если быстро дёргать край окна, картинка
  не успевает отрисоваться, по краям чёрные и белые квадраты; после этого окно секунд на 5 зависает при попытке
  перенести. При первой записи экрана зависли оба выхода HDMI, системный блок пищал, понадобилась перезагрузка.
  На AMD основного компьютера почти не видно, и зависания нет.
- **Разбор.** Ошибка движка. Пока край тянут мышью, Windows крутит свой модальный цикл: каждое `WM_SIZE` уже
  перерисовано синхронно (`LiveResize`), но его событие RESIZE остаётся в очереди. После отпускания кнопки главный
  цикл проигрывал всю очередь: на каждое событие — ожидание GPU и `ResizeBuffers` под устаревший размер. Отсюда
  зависание на секунды, а пересоздаваемые буферы без кадра давали мусор на краях. Замер на 300 шагах (окно 480×320):
  без исправления Intel D3D12 — 2,8 с, Intel D3D11 — 1,0 с, NVIDIA — 0,4–0,7 с, AMD — до 0,9 с; с исправлением —
  около 1 мс везде. Исправление: размер цепочки берётся по нынешнему окну (`src/app/application_events.cpp`),
  устаревшие события пропускаются. Зависание HDMI в системных журналах Windows следов не оставило: ни сброса
  драйвера (TDR), ни аварийного выключения; вероятно, оно связано с той же лавиной пересозданий под захватом экрана.
  **Что нашёл человек:** зависание и мусор при перетаскивании — автотесты окно мышью не тянули. Добавлено:
  живой тест «live resize storm» (`tests/render/resize_live.cpp`) — 300 изменений размера внутри
  `WM_ENTERSIZEMOVE`…`WM_EXITSIZEMOVE` и предел 0,05 с на разбор очереди; без исправления он падает на всех картах.

## Т-15. Повторная проверка перетаскивания окна (Windows, Intel и NVIDIA)

- **Зачем.** Исправление Т-14 убрало зависание после перетаскивания (замер — 1 мс вместо секунд). Остались ли
  полосы на краях *во время* перетаскивания, автотест не видит: это кадры DWM.
- **Приоритет:** блокирует выпуск; 15 минут.
- **Подготовка.** Стенд в Windows; сборка с исправлением уже лежит в `C:\gran\gran\bin`. В `cmd`:
  ```
  cd /d C:\gran\gran
  set GRAN_ADAPTER=intel
  bin\gran_gallery.exe
  ```
  Затем то же с `set GRAN_ADAPTER=nvidia`.
- **Шаги.**
  1. Быстро потаскайте правый нижний угол окна 10–15 секунд, как в прошлый раз.
  2. Отпустите и сразу возьмите окно за заголовок, перенесите.
  3. Повторите с `bin\gran_gallery.exe samples\glass.xml`.
  4. Если захочется записать экран — сначала без записи (в прошлый раз запись совпала с зависанием HDMI).
- **На что смотреть.** Шаг 2: окно переносится сразу, без паузы. Шаг 1: есть ли ещё полосы по краям и насколько
  они заметнее, чем на AMD.
- **Что прислать.** «Зависает / нет»; видео, если полосы остались, — в `tests/videos/`.
- **Результат.** _(заполняет проверяющий)_

Linux на стенде (Vulkan на NVIDIA, NVK, Intel ANV, lavapipe; окно X11; ASan, TSan, Valgrind) проверен
автоматически 2026-11-08 — итоги в [`docs/test_stand.md`](../../../docs/test_stand.md). Т-8 из задач 0.1.0 (живое окно
и захват Vulkan глазами) остаётся за стендом.
