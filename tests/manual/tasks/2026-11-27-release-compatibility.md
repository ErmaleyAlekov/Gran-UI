## Т-248. Совместимость C ABI и XML-разметки выпуска

Сначала пройдите [общие пункты ревью кода О-1…О-8](../README.md#code-review-rules), затем переходите к шагам этой задачи.

**Зачем.** Убедиться, что исправление из ветки выпуска сохраняет экспортируемые функции, раскладку типов C и возможность прочитать XML из исходного выпуска.

**Приоритет и время.** Перед выпуском, 10 минут при собранных библиотеках.

**Подготовка.** Нужны история Git с тегами, Python 3.9+, MinGW или Linux GCC, собранные `gran_c` и `libberesta.a` из той же конфигурации.

**Шаги.**

1. Из корня Gran в Windows запустите `python -B tools/ci/compatibility.py --branch main --library bin/gran_c.dll --beresta "../Dom lib C++"`. В Linux укажите путь к `libgran_c.so` и каталогу «Берёсты».
2. Запустите `python -B tools/ci/test_compat_schema.py`. Проверьте различие строгого и минорного режимов на добавлении необязательного атрибута.
3. На исходниках 0.3.0-dev повторите первую команду с `--branch release/0.2`. Ожидается ненулевой код возврата и имя несовместимой декларации. В CI используется целевая ветка запроса на слияние.

**На что смотреть.** Метки версии в выводе, реальные экспорты библиотеки, изменение типа при сохранении имени функции, добавление обязательного поля XML. Фрагменты руководства сначала проходят схему тега в контексте окна, контейнера или ресурсов. Для проверки исправления существующего ограничения XSD зафиксируйте точную пару старого и нового правил и пример, который демонстрирует исправление.

**Что прислать.** Платформу, тег, команду, код возврата и первую диагностическую строку.

## Результат

При ревью обнаружены пропуски изменения типа `gran_status`, номера ABI и сужения произвольного атрибута XML до типизированного.

## Разбор

Проверка компилирует сигнатуры, типы, значения констант и смещения полей относительно заголовка тега. Сужение произвольного XML-атрибута покрыто регрессионным тестом. Windows MinGW прошла сборку и 690 тестов. На `v0.2.0` проверены 23 примера, 4 тестовых документа и 40 валидных вариантов включения фрагментов документации. Строгий режим отклонил новый тип схемы `Track`.

Linux x86_64, Ubuntu в WSL. Заголовки X11–XCB и XCB распакованы локально из пакетов Ubuntu со сверкой SHA-512. Собраны `libgran_c.so` и статическая «Берёста» в одной конфигурации CMake.

- `python3 -B tools/ci/compatibility.py --branch main --library build-linux/libgran_c.so --beresta "$beresta"` завершилась с кодом 0. Первая строка `Compatibility: main / v0.2.0`. Проверены 23 примера, 4 тестовых документа и 40 вариантов включения фрагментов документации.
- `python3 -B tools/ci/test_compat_schema.py` завершилась с кодом 0. Пройдены все четыре теста, в том числе проверка добавления необязательного атрибута.
- Повтор команды с `--branch release/0.2` завершился с ожидаемым кодом 1. Первая строка `Compatibility: release/0.2 / v0.2.0`, диагностика `XSD schema/Track: unexpected declaration {'name': 'Track'}`.

`"$beresta"` указывал на временный каталог со ссылками на заголовки «Берёсты» и собранный CMake архив под именем `bin/libberesta.a`.
