Сначала пройдите [общие пункты ревью кода О-1…О-8](../README.md#code-review-rules), затем переходите к шагам этой задачи.

**Зачем.** Проверьте, что редактируется выбранный элемент и служебные поля переживают предпросмотр.

**Приоритет.** Желательно до выпуска. Оценка — 16 минут.

**Подготовка.** Откройте [папку снимка Т-260](../review/T-260/) в редакторе. Сборка для чтения кода не требуется.

**Шаги и критерии.** Уделите особое внимание О-1, О-3, О-5, О-6.

1. Проверьте повторное открытие и закрытие свойств, а также окно с одним глобальным токеном. См. `src/app/layout_inspector.cpp:7–81`.
2. Сверьте доступность глобального и локального токена с выбором области. См. `src/app/layout_panel_pages.cpp:10–66`.
3. Проследите источник события до области поиска поля и id изменяемого элемента. См. `src/app/layout_panel_actions.cpp:19–93`.
4. Выберите параметризованный шаблон, затем другой шаблон. Старые поля должны уйти вместе с обработчиками. См. `src/app/layout_panel_parameters.cpp:12–64`.

5. Откройте создание в выбранной области. Проверьте фильтр страниц для Tabs, исходное заполнение параметров, смену шаблона, сохранение порядка команд и передачу локального токена в ту же Insert. При отказе формы пользователь должен иметь возможность исправить ввод. Проверьте совпадение нового id с id ресурса и с уже существующим значением вкладки.

**Что прислать.** Укажите путь и строку, последовательность действий и нарушенный контракт. Запишите наблюдения в разделе ниже.

## Результат

src/app/layout_inspector.cpp:72-74 при открытии инспектора для элемента с правом Customization::INSERT подменяет parent = target и выставляет этот же target->id в список destination, из-за чего нажатие кнопки перемещения отправляет app.editLayout("Move", ...) с одинаковыми id и parent, пытаясь вложить элемент в самого себя.
