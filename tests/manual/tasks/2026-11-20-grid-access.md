# Ручные проверки: доступность таблиц и деревьев, проверка правки кодом (2.2.6)

Доработка 2026-11-20. Три части:

1. **UI Automation для `DataGrid` и `TreeView`.** Таблица — элемент DataGrid (шаблоны Grid, Table, Selection), строка
   заголовков — Header, заголовки — HeaderItem, строки — DataItem (SelectionItem, место «строка N из M»), ячейки —
   DataItem с GridItem и TableItem; дерево — Tree, строки — TreeItem (уровень Level, ExpandCollapse, лист — LeafNode).
   Фокус ввода остаётся у списка строк, а дикторам фокус — текущая строка дерева или текущая ячейка таблицы.
2. **Событие `cellEdit`:** код программы проверяет и может заменить значение правки ячейки до записи; отказ — подсказка
   у поля и состояние `<Invalid>`. Си-интерфейс `gran_event_set_cell` и обёртки Python, C#, Java.
3. **Долг 2.2.5:** признаки «ветка» и «раскрыта» у кнопки раскрытия ставит сама привязка списка (`NodeContent::branch`).

Автотесты (`grid access: *`, `uia grid: *`, `cell edit event: *`) вызывают провайдер UI Automation напрямую (без
UIAutomationCore и диктора) и правят ячейки в безоконном приложении. Они не видят, что **говорит** диктор, как Inspect
показывает дерево элементов, как ведёт себя настоящий клиент UI Automation (кэширование, события, виртуальные строки
при прокрутке) и как выглядит отказ правки под мышью.

Подготовка для всех задач (Windows, MinGW):

```bash
make -j16 all
```

```bash
bin/gran_gallery samples/grid.xml --debug
```

```bash
bin/gran_gallery samples/models.xml --debug
```

Инструменты: Экранный диктор (Ctrl+Win+Enter), Inspect.exe из Windows SDK
(`C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\inspect.exe`) или Accessibility Insights for Windows.

## Т-73. Таблица и дерево под Экранным диктором и в Inspect (Windows)

- **Зачем.** Провайдер отдаёт новые шаблоны и меняет «фокус для дикторов» (текущая строка или ячейка вместо списка).
  Риски, которых не видит тест: диктор молчит при ходьбе стрелками (событие фокуса не доходит или элемент ячейки
  каждый раз новый и клиент его не узнаёт), читает строку целиком вместо ячейки, не называет заголовок столбца, путает
  «развёрнуто/свёрнуто», у листа говорит «свёрнуто»; Inspect показывает пустые группы, двойные элементы, неверные
  Row/Column; у виртуальной таблицы после прокрутки GetItem возвращает чужую строку.
- **Приоритет:** до выпуска 0.3.0 · ~30 минут.
- **Подготовка.** Команды выше; запустите Inspect (режим UI Automation, «Watch Focus» включён).
- **Шаги.**
  1. `samples/grid.xml` (в этом примере только таблица, дерева `TreeView` нет — оно в `samples/models.xml`, шаг 6).
     В Inspect найдите элемент таблицы: окно «Gran UI — таблица» → «Заказы» (тип DataGrid, AutomationId `orders`);
     проще — «Watch Focus» и щелчок по ячейке таблицы.
     *(Уточнено 2026-11-20 после первой попытки: прежний текст «раскройте дерево элементов до таблицы» читался как поиск
     дерева в окне; к тому же у таблицы не было имени, и в Inspect она выглядела как пустая «таблица данных» — см. разбор ниже.)*
  2. Щёлкните по строке таблицы (не по полю фильтра). Нажимайте ↓ три раза, затем → два раза, затем ←.
  3. Включите Экранный диктор (Ctrl+Win+Enter) и повторите шаг 2. Нажмите Shift+↓ (выделение двух строк).
  4. В Inspect у таблицы откройте шаблон Grid: RowCount, ColumnCount; Table: ColumnHeaders. Выделите ячейку (Action → Grid
     → GetItem 5, 2, если в вашей версии Inspect есть вызов методов; иначе — просто посмотрите свойства GridItem у ячейки).
  5. Прокрутите таблицу колесом далеко вниз и снова походите стрелками с диктором.
  6. `samples/models.xml`: щёлкните по строке дерева «Отделы», с диктором пройдите стрелками ↓, ←, →, → по веткам и листьям.
  7. В Inspect у строки дерева нажмите ExpandCollapse → Collapse, затем Expand (кнопки в панели шаблонов); у листа — Expand.
  8. У строки таблицы в Inspect: SelectionItem → AddToSelection на невыделенной строке (таблица `orders` — множественное
     выделение), затем RemoveFromSelection.
- **На что смотреть.**
  1: таблица «Заказы» — тип DataGrid; под ней Header (заголовки «№», «Клиент»… без стрелки «▲» в имени, тип HeaderItem;
  у отсортированного — свойство AriaProperties `sort=ascending`), строки DataItem и ячейки DataItem;
  прокрутка таблицы и строка фильтров как отдельные пустые группы в «control view» не видны (поля фильтров — Edit
  с именами по заголовкам столбцов).
  2: Inspect («Watch Focus») прыгает по ячейкам: ↓ — та же колонка в следующей строке, → — соседняя ячейка; у ячейки
  GridItem.Row = номер записи, Column = номер столбца на экране, ContainingGrid — таблица; TableItem.ColumnHeaderItems — её заголовок.
  3: диктор при каждом шаге читает новую ячейку (значение и заголовок столбца, по возможности «строка N из M»), при
  выделении — «выбрано»; паузы или молчания нет.
  4: RowCount — число всех заказов (а не только видимых строк), ColumnCount — 5; ColumnHeaders — 5 заголовков.
  5: после прокрутки фокус и Row у ячеек соответствуют видимой записи; диктор читает правильные строки.
  Строки, ушедшие из видимой части, остаются у клиента «виртуальными» (`IsOffscreen: true`, VirtualizedItem, без детей),
  Realize прокручивает к ним; дети списка — только построенные строки. Дерево Inspect — снимок: после прокрутки F5.
  6: у строки дерева — «уровень 1/2/3», «развёрнуто»/«свёрнуто»; у листа — без «свёрнуто» (лист); ← на раскрытой —
  «свёрнуто», → — «развёрнуто».
  7: Collapse/Expand меняют дерево на экране, у листа Expand — ошибка (Inspect пишет InvalidOperation), дерево не меняется.
  8: AddToSelection добавляет строку к выделенным (подсветка на экране), RemoveFromSelection снимает только её.
- **Что прислать.** Отметку по шагам; скриншот Inspect с деревом элементов таблицы (шаг 1) и со свойствами ячейки
  (шаг 2); если диктор молчит или читает не то — запишите, что именно он сказал (или короткое видео со звуком в
  `tests/manual/results/`).
- **Результат.** Пользователь, 2026-11-20…21: дерево элементов таблицы и свойства строк и ячеек проверены в Inspect,
  найдено 5 ошибок (скрины — `tests/manual/results/2026-11-20-T-73/`), все исправлены.

  | № | Что нашёл человек | Причина | Исправление |
  |---|---|---|---|
  | 1 | Таблицу «не найти» в Inspect (`1-…`) | у таблицы нет имени; шум: пустые Text у заголовков, «№ ▲» в имени; неясный текст шага | `a11y::hiddenText`, сортировка — `AriaProperties sort=…`, `accessibleName` в примерах, шаг переписан |
  | 2 | У строк все свойства — `UIA_E_ELEMENTNOTAVAILABLE` (`2a…2c`) | виртуальная таблица пересоздаёт строки при прокрутке, клиентам не сообщалось; RuntimeId по адресу узла (риск «чужой» строки) | `ui::Node::serial`, событие `StructureChanged` на общий контейнер удалений |
  | 3 | То же на другой строке после п. 2 (`3-…`) | элемент был привязан к копии строки, а не к записи | элемент по записи (`ItemKey`, версия записей), вне экрана — виртуальный: `IsOffscreen`, VirtualizedItem, `Realize` |
  | 4 | У виртуальной строки ошибки RuntimeId, LegacyAccessible, Children (`4-…`) | `get_FragmentRoot` отвечал «недоступен» | корень фрагмента отдаётся и виртуальной строке |
  | 5 | Видимые строки в дереве Inspect без детей (`5-…`, `6-…`) | событие уходило только списку, построенная заново строка не сообщалась | `ChildrenInvalidated` на каждую построенную строку (`nodeAdded` → `AccessTree::added`) |

  **Разбор (Claude).** Человек нашёл то, чего не видели автотесты и анализаторы: тесты вызывали провайдер напрямую,
  по одному методу и брали элементы уже после изменения дерева, а внешний клиент держит элементы с прошлого раза
  и собирает свойства цепочкой (RuntimeId — через корень фрагмента). В автоматику добавлено: тесты `uia grid: rebuilt row
  is a new element`, `scrolled row stays the same element`, `rows after thumb jumps`, `grid access: removal container`,
  `added rows`; проверка внешним клиентом `tools/uia_scroll_check.ps1` (кандидат в `make test-render`) и обход дерева
  `tools/uia_walk.ps1`. Шаги 2–8 (стрелки, диктор, Grid, дерево `models.xml`, выделение) отдельно не отмечены —
  при желании пройти при следующей проверке.

## Т-74. Проверка правки кодом под живой мышью (Windows; по желанию — Linux)

- **Зачем.** `samples/grid.xml` теперь проверяет правку кодом программы (`onCellEdit="checkOrder"`, обработчик —
  в `gran_gallery`): клиент не пустой (пробелы по краям срезаются), сумма от 1 до 10 000 000. Отказ оставляет редактор
  открытым с подсказкой. Риски: подсказка не видна или «прилипает» после исправления, редактор закрывается при отказе,
  Tab после отказа уходит в соседний столбец, щелчок мимо записывает отклонённое значение.
- **Приоритет:** до выпуска 0.3.0 · ~10 минут.
- **Подготовка.** `bin/gran_gallery samples/grid.xml --debug` (на стенде Альт — `make -j8 all` в свежей копии и то же без `.exe`).
- **Шаги.**
  1. Выделите строку, F2 в столбце «Сумма», наберите `0`, Enter. Наведите мышь на поле редактора.
  2. Наберите `25000`, Enter.
  3. F2 в «Клиент», сотрите всё, Enter. Затем наберите «  Ромашка  » (с пробелами по краям), Enter.
  4. F2 в «Сумма», наберите `20000000`, нажмите Tab.
  5. Ещё раз F2 в «Сумма», наберите `20000000` и щёлкните по другой строке таблицы.
  6. Ctrl+Z после шага 2 и шага 3.
- **На что смотреть.**
  1: запись не меняется, редактор остаётся открытым с красным подчёркиванием (`Invalid`), при наведении — подсказка
  «Сумма — от 1 до 10 000 000»; внизу справа — тот же текст.
  2: значение записано, редактор закрыт, внизу «Записано: sum = 25000».
  3: пустой клиент — отказ «Клиент не может быть пустым»; «  Ромашка  » записывается как «Ромашка» (без пробелов).
  4: Tab при отказе не переходит в соседний столбец, редактор остаётся с ошибкой.
  5: щелчок мимо закрывает редактор **без записи** (уход фокуса при отказе отменяет правку).
  6: отмена возвращает прежние значения по одному шагу на правку; отказанные правки шагов не дают.
- **Что прислать.** Отметку по шагам; скриншот шага 1 с подсказкой.
- **Результат.** Всё работает как и описан, но есть нюанс - последний шаг 6 Ctrl+Z работает только в режиме редактирования. Написано после шага 2 и 3, а в них есть enter, что выводит из режима редактирования.

  **Разбор (Claude, 2026-11-21).** Прошло. Нюанс шага 6 подтвердился: в `samples/grid.xml` не было команды `gran:undo`
  с Ctrl+Z, поэтому вне редактора Ctrl+Z ничего не делал (шаг отмены писался, а клавиши не было), в поле работала
  своя история поля. Ожидание в задаче было неверным для примера. **Исправлено:** в пример добавлены команды
  `undo` (Ctrl+Z) и `redo` (Ctrl+Y, Ctrl+Shift+Z); тест `cell edit event: Ctrl+Z after Enter` (запись Enter, Ctrl+Z
  возвращает прежнее, Ctrl+Y — новое). Чего не поймали автотесты: тесты правки отменяли через `Application::undo`,
  а не клавишей в примере.

## Т-75. Ревью: провайдер UI Automation таблиц и деревьев, событие cellEdit в ядре и Си-интерфейсе

  `cellEdit` может менять дерево и модель посреди окончания правки; Си-интерфейс держит указатель на текущее событие
  в `thread_local`). Ошибки здесь — утечки и двойные `Release`, висячие узлы у элементов, переживших строку, выход
  `size_t` за `int`, исключение, ушедшее в UI Automation, повторный вход в окончание правки.
