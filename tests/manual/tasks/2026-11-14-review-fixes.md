## Т-45. Слова в поле и потеря фокуса посреди нажатия (Windows, Альт)

- **Зачем.** (1) Ctrl+←/→ и Ctrl+Backspace/Delete раньше шагали по символу — теперь по словам; надо убедиться, что на
  живой клавиатуре это совпадает с привычками ОС (Блокнот, браузер) и не задевает команды. (2) Окно теперь отпускает
  захват мыши при `WM_KILLFOCUS` / `FocusOut`: проверяем, что после Alt+Tab с зажатой кнопкой ничего не «залипает».
- **Приоритет:** желательно до выпуска 0.2.0 · ~10 минут на ОС.
- **Подготовка.**
  ```
  make
  bin/gran_gallery samples/commands.xml
  ```
  В Альте сборка уже лежит на стенде (рабочее дерево 2026-11-14 со всеми правками, отдельно от вашего `~/gran-stand/src`):
  ```
  cd ~/gran-stand/t45
  ./bin/gran_gallery samples/commands.xml
  ```
- **Шаги.**
  1. Щёлкните в поле ввода, наберите `один  два, три`. Нажмите Ctrl+← несколько раз, затем Ctrl+→.
  2. Поставьте каретку в конец и нажмите Ctrl+Backspace дважды; затем Home и Ctrl+Delete.
  3. Наберите текст снова, выделите Ctrl+Shift+← до начала.
  4. В поле нажмите Alt+←.
  5. Нажмите левую кнопку мыши на кнопке окна и, **не отпуская**, нажмите Alt+Tab (переключитесь в другое окно),
     отпустите кнопку там. Вернитесь в галерею и поводите мышью над кнопками, затем щёлкните одну.
  6. То же, что шаг 5, но кнопку зажмите в поле ввода и протяните выделение, затем Alt+Tab.
- **На что смотреть.**
  1. Windows: Ctrl+← — к началу слова слева (`три` → `два,`… → `один`); Ctrl+→ — к началу следующего слова (после
     `один` каретка встаёт перед `два`). Альт: Ctrl+→ — к **концу** слова (как в GTK). Сравните с Блокнотом / gedit.
  2. Ожидаю: первый Ctrl+Backspace стирает `три` (остаётся `один  два, `), второй — `, ` (остаётся `один  два`: запятая —
     отдельное «слово» из знаков, пробелы перед ней пропускаются). Home, Ctrl+Delete: в Windows стирается `один  `
     (до начала следующего слова), в Альте — `один` (до конца слова). Если Блокнот / gedit делают иначе — напишите как.
     Ctrl+Z возвращает стёртое. Del без Ctrl в поле стирает символ, а не запускает команду `Del` окна.
  3. Выделение растёт по словам.
  4. Каретка **не** двигается (Alt+← — сочетание команд); если в разметке есть команда на Alt+←, срабатывает она.
  5. После возврата кнопки подсвечиваются под мышью как обычно, щелчок работает; никакая кнопка не осталась «нажатой»,
     щелчок не случился сам при возврате.
  6. Выделение остановилось на месте, мышь после возврата не тянет его дальше без нажатия.
- **Что прислать.** «Прошло / не прошло» по шагам и ОС; для шагов 1–2 — чем поведение отличается от Блокнота/gedit.
- **Результат:** Всё норм, ничем не отличается.
- **Разбор (2026-11-14):** прошло на Windows и Альте — шаги и стирание по словам совпадают с Блокнотом / gedit, после
  Alt+Tab с зажатой кнопкой ничего не залипает. Захват ОС в живом окне автотесты не видят (AppDriver идёт мимо
  оконной процедуры); общий код отмены нажатия покрыт `driver keys: focus loss`.

## Т-46. Ревью: таблица клавиш правки текста и шаги по словам

- **Зачем.** Таблица `caretMove` / `eraseMove` станет поведением полей на macOS (M6), а проверить её на Mac мы не можем.
  Свежий взгляд на соглашения и на границы (пустой текст, каретка в конце, UTF-8) дешевле, чем ошибка у пользователя.
- **Приоритет:** когда будет время (до шага M6) · ~20 минут.
- **Подготовка.** Файлы: `include/gran/input/internal/text_keys.hpp`, `src/input/text_keys.cpp`,
  `src/input/text_word_steps.cpp`, `src/input/text_words.cpp` (`isWordGap`), `src/input/command_keys.cpp` (`fieldOwns`),
  таблица «Сочетания правки текста» в `docs/architecture.md`.
- **Шаги — на что смотреть.**
  1. Таблица по ОС: верно ли записаны привычки Windows, Linux (GTK/Qt) и macOS; чего не хватает (Option+↑/↓ —
     абзац на macOS, Control+A/E — emacs-сочетания Cocoa).
  2. `fieldOwns`: какие сочетания поле теперь забирает у команд и не отнимет ли это привычную команду (Ctrl+PageUp
     оставлен командам намеренно).
  3. Шаги по словам: каретка в конце и в начале текста, только пробелы, многобайтовые символы, перевод строки в
     `TextArea` — нет ли шага, который не двигает каретку или выходит за текст.
- **Что прислать.** Ссылки «`файл:строка` или строка таблицы — что не так». Всё верно — так и напишите.
- **Результат:** В коде шагов по словам и таблицах ОС почти всё верно, однако в command_keys.cpp есть баг с маской CHORD, в которую не включён MODIFIER_META. Из-за этого на macOS поле в фокусе по ошибке забирает себе сочетания с физическим Control (как обычный ввод без модификаторов), а также Cmd+Y (которое на Mac вызывает историю, а не Redo) и Ctrl+Enter в однострочных полях, хотя он нужен только для TextArea. Шаги по словам безопасны по границам UTF-8, но для многострочных полей и поведения macOS стоит учесть, что isWordGap перескакивает пустые строки насквозь, а в macMove не хватает перехода по абзацам (Option+↑/↓) и emacs-привязок (Control+A/E/K).
- **Разбор (2026-11-14):** все пять замечаний верные, исправлено.
  1. **`CHORD` без `MODIFIER_META`** (`command_keys.cpp`) — сочетание с физическим Control на macOS выглядело для поля как
     ввод без модификаторов, и поле его забирало. Теперь `META` в маске; поле забирает `META`-сочетание только по таблице
     (Control+A/E/K). Попутно: символ (`CHARACTER`) с `META` больше не набирается (`keyboard_input.cpp`).
  2. **Cmd+Y на macOS** — поле считало его повтором. Теперь Mod+Y — повтор только в Windows и Linux (`editingChord`,
     `historyKey`); на macOS Cmd+Y достаётся командам, повтор — Cmd+Shift+Z.
  3. **Ctrl+Enter в однострочном поле** — поле забирало его у команд, хотя смысл у него есть только в `TextArea`
     (отправка по `submitKey`). Теперь `editingChord` получает узел поля: Mod+Enter — только у `TextArea`; у `Input`
     сначала ищется команда, а без неё Enter работает как раньше (`onSubmit`).
  4. **`isWordGap` проскакивал пустые строки** — перевод строки был «промежутком». Теперь пробел — промежуток, перевод
     строки — остановка (`isLineBreak`): шаг от края строки переходит на соседнюю строку и дальше не идёт, как в
     Блокноте и gedit. Это касается всех ОС.
  5. **Абзацы и emacs на macOS** — добавлены Option+↑/↓ (абзац; уже на краю — соседний), Control+A/E (края абзаца),
     Control+K (стереть до конца абзаца; в самом конце ничего не стирает — перевод строки Cocoa удалил бы, это не сделано).
     Таблица macOS вынесена в `src/input/text_keys_mac.cpp`. Прочие emacs-сочетания (Control+B/F/N/P/D/H) не добавлены:
     если нужны — скажите.

  **Что нашёл человек и чего не поймала автоматика:** все пять. Пункты 1–3 и 5 — поведение macOS, которое тесты на
  Windows и Linux не исполняют, а таблицу проверял тест, написанный по моему же пониманию соглашений. Пункт 4 тест
  `text keys: word navigation` не ловил: в нём не было перевода строки. **Что добавлено в автоматику:** `text steps: …`
  (таблица macOS с абзацами и emacs, `META` в Windows, остановка на переводе строки, пустые строки, абзацы с краями),
  `driver field: …` (Ctrl+Enter — команда в `Input` и не команда в `TextArea`, символ с `META` не набирается, Mod+Y по ОС).
