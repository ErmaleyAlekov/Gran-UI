# Ручные проверки (человек в контуре)

Автотесты, санитайзеры и отладочные слои GPU не видят всего: как выглядит кадр, как окно ведёт себя под живой мышью,
что показывает захват кадра на настоящей видеокарте, что происходит за часы работы. Такие проверки делает человек
по подробным задачам. Задачи готовятся после каждой большой доработки (правило проекта: автотесты + анализаторы +
ручные задачи), файлы — в [`tasks/`](tasks/).

## Как устроена задача

`## Т-<номер>. <название>` и поля: **Зачем** (риск, который проверяем, и почему автоматика его не видит),
**Приоритет** и время, **Подготовка** (точные команды), **Шаги**, **На что смотреть**, **Что прислать**,
**Результат** (заполняет проверяющий) и **Разбор** (заполняет разработчик: что исправлено, какая автоматическая
проверка добавлена, чтобы в следующий раз ловить это без человека).

Приоритеты: **блокирует выпуск** — без этой проверки версию не выпускаем; **до выпуска** — желательно;
**когда будет время** — полезно, но не срочно.

## Общие пункты ревью кода (О-1…О-8)

В Gran UI ручное ревью кода охватывает реализацию движка, его заголовки и авторские шейдеры. Тестовые документы и примеры служат входными данными для проверок.

Смотреть в каждой задаче ревью до её собственных шагов:

- **О-1. Значения извне.** Каждое число и строка из документа, схемы, файла, аргумента Си-интерфейса или окружения проверены до `static_cast`, до индексации, до `resize`/`reserve` и до сужения типа.
- **О-2. Границы без переполнения.** Проверки вида `len > size - pos`, а не `pos + len > size`; произведения размеров — в 64 битах или с проверкой.
- **О-3. Владение и время жизни.** Висячие указатели, ссылки, `string_view` и итераторы после правки дерева, после освобождения документа, после выхода из области; двойное освобождение.
- **О-4. Пределы на враждебном входе.** Рекурсия без предела глубины, квадратичное и экспоненциальное время, рост памяти без предела.
- **О-5. Ошибки.** Свои классы исключений; исключение не проходит через Си-границу; состояние объекта после исключения согласовано; `catch (...)` не глотает настоящие ошибки.
- **О-6. Сообщения.** Тексты для пользователя — из каталога (`messages_ru.cpp` / `messages_en.cpp`), не литералы.
- **О-7. Потоки.** Общее изменяемое состояние (глобальные, `static`, кэш, реестры обёрток) — гонки.
- **О-8. Правила проекта** (вторично, только если мешает читать): ≤ 25 строк в функции, ≤ 5 функций в файле, ≤ 5 параметров, нет исполняемого кода в заголовках, двуязычные комментарии.

Ответ — «`файл:строка` — что не так — какой вход это вызовет». Если всё чисто — какие пункты смотрели.
